# 赛题2：三维空间数据的高效读写

## 1. 赛题目标

面向大规模规则三维浮点数据，设计一种**无多副本、低冗余、三方向访问均衡**的存储结构与高速读写算法库。

系统需要在单机环境下支持：

- 原始三维浮点数组与优化存储格式之间的双向转换；

- X、Y、Z 三个方向的任意切片读取；

- 连续多切片读取；

- 主维度单列读取；

- HDD、SATA SSD、NVMe SSD 等不同存储设备；

- 可配置内存上限；

- 单进程、多线程运行；

- 可选 CUDA 加速。

  核心目标是在不保存 X、Y、Z 三份完整数据副本的前提下，使三个方向的读取效率尽量接近顺序存储主维度的连续读取性能。

---

## 2. 必须实现的功能

### 2.1 数据转换

程序应支持：

```text
原始 .dat / 浮点数组
        ↓ 预处理
自定义优化存储格式
        ↓ 读取与还原
标准切片文件或原始三维数据
```

预处理过程包括分块、重排、索引生成、压缩和优化格式写入。

**预处理时间不计入性能评分，但预处理后生成的全部文件计入存储空间评分。**

### 2.2 切片读取

对于尺寸为 `Nx × Ny × Nz` 的三维数据体，必须支持：

- 固定 X，读取 `Ny × Nz` 切片；
- 固定 Y，读取 `Nx × Nz` 切片；
- 固定 Z，读取 `Nx × Ny` 切片；
- 连续读取多个相邻切片；
- 沿主维度读取单列数据。

### 2.3 正确性

数据必须完整还原，且：

```text
单点相对误差 < 0.001
```

正确性属于否决项。若结果错误、维度错误、数据顺序错误或误差超限，则性能成绩无效。

---

## 3. 评分标准

| 项目       |   分值 | 说明                                            |
| ---------- | -----: | ----------------------------------------------- |
| 功能正确性 | 否决项 | 数据完整还原，单点相对误差小于千分之一          |
| 性能指标   |     60 | 按 X、Y、Z 三个方向的随机和连续切片综合耗时评分 |
| 存储指标   |     20 | 总存储空间小于原始数据的 1.5 倍可得满分         |
| 文档指标   |     20 | 存储结构、索引原理、算法实现和测试效果各 5 分   |

性能得分公式为：

```text
性能得分 = 基准时间 / 实际综合时间 × 60
```

基准时间不是固定值，而是所有参赛成果中的最短综合耗时。

---

## 4. 性能测试口径

性能测试包含六类任务：

| 测试项   | 内容                   |
| -------- | ---------------------- |
| Random-X | X 方向随机切片 100 次  |
| Random-Y | Y 方向随机切片 100 次  |
| Random-Z | Z 方向随机切片 100 次  |
| Batch-X  | X 方向连续大切片 10 次 |
| Batch-Y  | Y 方向连续大切片 10 次 |
| Batch-Z  | Z 方向连续大切片 10 次 |

综合时间按六项平均计算：

```text
T综合 =
(
  T_random_x +
  T_random_y +
  T_random_z +
  T_batch_x +
  T_batch_y +
  T_batch_z
) / 6
```

建议同时记录：

- 每类任务总时间；
- 单次平均时间；
- 吞吐量；
- P50、P95、P99 延迟；
- 峰值内存；
- CPU 使用率；
- 写出文件大小。

### 计时范围

性能计时从接收切片请求开始，到完成标准格式文件写出结束，包括：

```text
索引定位
→ 磁盘读取
→ 解码或解压
→ 内存重排
→ 切片拼接
→ 标准格式写出
```

不能只统计 `read()`、`pread()` 或文件映射时间。

## 5. 存储要求

优化格式的全部文件均计入存储空间，包括：

- 主数据文件；

- 索引文件；

- 元数据文件；

- 偏移表；

- 压缩信息；

- 校验信息；

- 运行必需的辅助文件。

  满分条件：

```text
优化格式总大小 < 原始数据大小 × 1.5
```

禁止采用 X、Y、Z 三份完整数据副本。推荐将空间倍率控制在：

```text
1.00 ～ 1.10
```

---

## 6. HDD 与 SSD 的针对性要求

程序应针对不同磁盘类型使用不同的 I/O 策略，不建议使用统一参数。

### 6.1 HDD 优化重点

HDD 的主要瓶颈是机械寻道和旋转延迟，应优先减少随机 I/O。

推荐策略：

- 使用较大的三维数据块；

- 按文件偏移对待读取块排序；

- 合并相邻或距离较近的 I/O 请求；

- 降低并发随机读取线程数量；

- 尽量将离散读取转换为连续读取；

- 使用较大的顺序预读窗口；

- 避免大量小块 `pread()`；

- 连续切片采用流水式预取；

- 对缓存块使用 LRU 或方向感知缓存。

  HDD 重点指标：

```text
寻道次数
随机 I/O 数量
平均连续读取长度
读取放大率
```

### 6.2 SSD / NVMe 优化重点

SSD 没有机械寻道，适合更高并发和更深的 I/O 队列。

推荐策略：

- 使用中等或较小的数据块；

- 增加异步 I/O 队列深度；

- 使用多线程或 `io_uring` 并发读取；

- 批量提交离散块请求；

- 使用内存池减少频繁分配；

- 使用页对齐缓冲区；

- 采用双缓冲或多级流水线；

- NVMe 环境下充分利用多队列能力；

- 对大切片使用并行读取和并行拼接。

  SSD 重点指标：

```text
I/O 队列深度
并发请求数
带宽利用率
CPU 开销
内存拷贝次数
```

### 6.3 建议提供的运行模式

```bash
reader --storage hdd
reader --storage ssd
reader --storage nvme
```

不同模式应自动调整：

- 数据块大小；
- 读取线程数；
- I/O 队列深度；
- 预取距离；
- 缓存容量；
- 请求合并阈值。

## 7. 推荐存储结构

推荐采用：

```text
文件头
+ 块索引
+ 三维分块数据
+ 可选压缩信息
+ 校验信息
```

数据体划分为固定或半固定大小的三维块：

```text
Bx × By × Bz
```

块可以采用：

- Morton 顺序；

- Hilbert 顺序；

- 分层分块顺序；

- 按设备类型优化的自定义块顺序。

  索引至少需要支持：

```text
切片坐标
→ 相关块坐标
→ 块编号
→ 文件偏移
→ 读取范围
```

设计目标是：

- 三方向访问均衡；
- 索引可常驻内存；
- 减少小 I/O；
- 控制读取放大；
- 支持批量请求合并。

---

## 8. 内存和并行限制

程序必须满足：

- 单机运行；

- 单进程；

- 多线程；

- 不使用多节点并行；

- 内存使用可配置；

- 内存超过 2 GB 时必须支持限制最大使用量；

- 优先使用 C/C++；

- 可使用 CUDA、OpenMP、oneTBB、io_uring 等；

- 禁止使用商用闭源库。

  建议提供：

```bash
reader   --input volume.dat3d   --axis x   --index 100   --max-memory 2048M   --threads 16   --storage nvme
```

## 9. 正确性测试

至少验证：

- 随机单点；

- 首尾边界点；

- X、Y、Z 任意切片；

- 连续多切片；

- 主维度单列；

- 边界块；

- 多线程重复运行；

- NaN 和 Inf；

- 完整数据还原。

  建议输出：

```text
最大绝对误差
最大相对误差
平均相对误差
超限点数量
数据顺序检查结果
```
