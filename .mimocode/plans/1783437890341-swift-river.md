# ERWT3D Tri-Axis Fixed-Rate 探索平台计划

## 目标

从"单文件 Morton 优化器"升级为"三轴物理连续布局探索平台"。先用 ZFP fixed-rate scanner(P1)判断 AB-ZFP-FR++ 方向是否成立,再视结果推进 P2-P3。

当前计划聚焦 **P1 scanner 的可执行实现**,P2-P3 为方向性框架。

## 背景:为什么跳出当前 Morton 主线

当前 Superblock 按 Z-Y-X 排布(`writer.cpp:188-192`),导致 X 切片触及 ~1520 个 superblock 而 Z 只需 494 个连续区域。HDD 优化(`sb_hdd.cpp` 的 read window/gap/readahead)本质是"在坏布局上减少寻道"。天花板已被布局锁死。

tri-axis 布局的目标:让 X/Y/Z 三轴切片都变成大顺序读,从根本上消除随机访问。

## 仓库现状确认

- 格式头:`format.hpp:31-45`,256B `ERWT3DHeader`,reserved[22] 已被 panels/planes/compression-index/sidecar 占用
- 压缩依赖:仅 LZ4(`CMakeLists.txt:15-23,64-68`),**无 ZFP**
- CMake:`CMakeLists.txt:46-58` 集中管理 LIB_SOURCES,tools 在 :71-109
- bench_contest:`erwt3d_bench_contest.cpp:90-105` 用 `ftruncate` 预创建输出文件,严格计时覆盖 read+decode+scatter+write(:108-194),close 在计时外(:197-199)
- reader API:`reader.hpp:34-36,75-77`,profile 结构 `IOProfile`(`sb_plan.hpp:74-85`)
- verify 误差逻辑:`erwt3d_verify.cpp:58-67` — `relErr = absErr / max(absRef,1e-12)`,近零值(absRef<=1e-6)用绝对阈值,否则 `relErr >= 1e-3` 失败
- HDD 机器:`sb_hdd.cpp` 的 `buildWindows`+`adviseSequential`+`prefetchWindows(depth=20)` 是 axis-agnostic 的,可直接复用
- 统一入口:`erwt3d_main.cpp:28-58` 是 exec 包装器,新命令需注册 `isKnownCommand`+`resolveBinary`
- 流式 raw 读取模板:`erwt3d_precompute_x.cpp:70-86` 的 z-layer pread 模式
- ThreadPool:`thread_pool.hpp:13-61`,`submit()` 返回 future

## 核心扫描算法

### 1. 流式 raw 读取(复用 precompute_x 模式)

主线程顺序读取 z-layer,通过 `pread` 按 `rowOff = z * nx * ny * sizeof(float)` 读整层(`erwt3d_precompute_x.cpp:72-73` 模式)。在内存中累积 `slabZLayers` 层(默认 64)构成一个 slab。

slab 大小:`nx * ny * slabZLayers * 4` 字节。50GB 维度(2001×2201×64)≈ 1.07GB。可通过 `--slab-z-layers 16` 降到 ~270MB。

### 2. Block 提取

从 slab 提取 4×4×4 块,按 **raw X-Y-Z 顺序**(block origin `(bx, by, bz)`,均为 4 对齐):

```
block[(iz*4+iy)*4+ix] = slab[((bz+iz)*ny + (by+iy))*nx + (bx+ix)]
```

边缘不足 4 的维度:零填充(文档化此选择)。

### 3. ZFP fixed-rate 压缩/解压(per block × per rate)

ZFP 文档确认:fixed-rate 模式 `zfp_stream_set_rate(stream, rate, zfp_field_3d, 3)`,每个 4³ block 用固定 bits = rate × 4³ = rate × 64 bits。float32 的 maxbits 最小 9。

```cpp
zfp_field* field = zfp_field_3d(blockBuf, zfp_type_float, 4, 4, 4);
zfp_stream* zs = zfp_stream_open(field);
zfp_stream_set_rate(zs, rate, zfp_field_3d, 3);
bitstream* bs = stream_open(compBuf, compBufSize);
zfp_stream_set_bit_stream(zs, bs);
zfp_compress(zs, field);       // 压缩
zfp_decompress(zs, fieldDec);  // 解压到 fieldDec
stream_close(bs);
zfp_stream_close(zs);
zfp_field_free(field);
```

每线程持有独立的 `blockBuf`(64 floats)、`compBuf`(ZFP 最大块大小)、`fieldDec`(64 floats)、`zfp_stream`/`bitstream`。通过 `thread_local` 或 per-thread 预分配。

### 4. 误差检查(per point,对齐 verify)

严格复用 `erwt3d_verify.cpp:58-67` 逻辑:

```cpp
bool isFailed(float ref, float actual, double relTol, double zeroAbsTol, double& relErr) {
    double absErr = std::abs((double)ref - (double)actual);
    double absRef = std::abs((double)ref);
    relErr = absErr / std::max(absRef, 1e-12);
    if (absRef <= zeroAbsTol) return absErr > zeroAbsTol;
    return relErr >= relTol;
}
```

一个 block 的 64 个点中**任意一个**失败 → 该 block 标记为 exception block。

### 5. 统计聚合(per rate)

- `exception_ratio` = exceptionBlocks / totalBlocks
- `max_rel_error` = 全局最大 relErr
- `p99_rel_error` = 收集所有 block 的 max-relErr 到 vector,slab 结束时排序取 99 百分位
  - 内存:8.5M blocks × 8 bytes × 6 rates ≈ 408MB(50GB 全量)。**若超内存预算**,改用 reservoir sampling 100K 样本(~5MB)
- `avg_compressed_bits` = 所有 block 的 compBits 均值(验证 fixed-rate 是否真的固定)

### 6. 多线程策略

**per-slab 并行**:主线程读 slab → 将 slab 内的 blocks 分发给 `ThreadPool`(`thread_pool.hpp:20` `submit()`)。每个 task 处理一个 block 的所有 rate,返回 `BlockResult{rateStats[6]}`。收集 futures,`get()` 后聚合,再读下一个 slab。

优势:block 数据只从 slab 读一次,复用于 6 个 rate。

### 关键发现

1. **近零值是 exception 的绝对主导因素**。ZFP fixed-rate 的 block 浮点指数由 block 中最大值决定,零值的量化误差 ~0.03~0.27,远超 1e-6 的绝对阈值。

2. **20GB 数据有 11% 近零点 → 10.39% 近零 exception blocks(rate=16)**。非零值的 rel_err exception 仅 0.82%。

3. **50GB 数据有 6% 近零点 → 73.6% 近零 exception blocks**。因为 4×4×4 block 中只要有 1 个近零值就标记为 exception,6% 点级近零 → 73.6% 块级近零。

4. **rate=16 是 20GB 的甜蜜点**:rel_err exception 仅 0.82%,如果用 zero-aware exception 排除近零块,实际 exception = 0.82%,total_ratio = 1.5 + 0.008 ≈ 1.508x。

5. **50GB 在任何 rate 下都无法满足 1.5x**:即使 rate=4(main_ratio=0.375),加上 73.6% 近零 exception = 1.111x,但 rel_err exception=100% 不可用。

### P1 决策

**命中"近零值大量失败"条件 → 必须做 zero-aware exact exception。**

**下一步方向:**
- **20GB**: rate=16 + zero-aware exception 有望达标。rel_err exception 0.82%,近零块存原始数据。total_ratio ≈ 1.5x。进入 P2。
- **50GB**: pure fixed-rate 不可行。需要:(a) 提高 zero_abs_tol(如 1e-4 替代 1e-6),或 (b) 对近零块用 fixed-accuracy/reversible 模式,或 (c) 转 P5 MAP-RPC。
- **zero-aware exception 设计**:对含近零值(absRef ≤ zeroAbsTol)的 block,不依赖 ZFP,直接存原始 4×4×4(256 bytes)或用 ZFP reversible 模式。

结果文件: `/mnt/d/CUP/zfp_scan_20gb.json`, `/mnt/d/CUP/zfp_scan_50gb.json`

- `tools/erwt3d_convert_tri.cpp`
- `tools/erwt3d_bench_tri.cpp`
- `tools/erwt3d_verify_tri.cpp`

### TriHeader 框架

```cpp
struct TriHeader {
    char magic[8];      // "ERWT3DT"
    uint32_t version;
    uint64_t nx, ny, nz;
    uint32_t block_x, block_y, block_z;  // 4,4,4
    uint32_t codec;     // raw/lz4/zfp
    uint32_t rate_bpv;
    uint32_t flags;
    uint64_t axis_offsets[3];
    uint64_t axis_bytes[3];
    uint64_t exception_index_offset;
    uint64_t exception_data_offset;
    uint64_t exception_count;
    uint64_t reserved[32];
};
```

### 物理布局

每个 axis 文件把该轴的 block index 放最外层:
- `axis_x.bin`:bx outer → bz → by → block
- `axis_y.bin`:by outer → bz → bx → block
- `axis_z.bin`:bz outer → by → bx → block

读取 X=i 时:`bx = i/4`,读取 `axis_x.bin` 中 bx 对应的连续 slab 段,一次 pread。

### 复用点
- HDD 机器:`sb_hdd.cpp` 的 `buildWindows`+`adviseSequential`+`prefetchWindows` 是 axis-agnostic,直接复用
- Writer 模板:镜像 `writer.cpp:148-424` 的流式 z-scan + scatter 模式
- Sidecar 模板:镜像 `erwt3d_precompute_x.cpp:58-113` 的 streaming z-chunk writer

### Bench 框架
`erwt3d_bench_tri` 复用 `erwt3d_bench_contest.cpp:90-105` 的 ftruncate 预创建 + 严格计时口径,但读取调 `TriReader::readSlice`。Profile 输出对齐 `IOProfile`(`sb_plan.hpp:74-85`)。

## P3:Exception sidecar

**目标**:让 correctness 过关(rel err < 1e-3 否决项)。

### 两种方案
- **E1 global exception**:`exception.bin` 存一份 canonical block,三轴共享。exception < 1% 时用。
- **E2 axis-local**:`exception_x/y/z.bin` 各存一份,按 slab 排序。exception 3-10% 时用。

P3 先做 E1,慢了再做 E2。
