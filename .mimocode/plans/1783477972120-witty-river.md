# Tri-axis Writer HDD 顺序写修复计划

## 问题

三轴布局按"轴最优读取"排列 block（X: bx外, Y: by外, Z: bz外）。z-slab 处理顺序是 bz→by→bx，与 X/Y 布局不匹配，排序后仍有 3.2 万次寻道。

## 方案分析

### 不能统一布局
三轴独立布局的核心价值：每轴切片读取只需一个连续 slab。若统一为 Z 布局，X/Y 切片变成 stride 访问（每隔 bxCount*blockBytes 读一个 blockBytes），HDD 上是灾难。

### 不能改变处理顺序
raw 是 X-Y-Z row-major，z-slab 是唯一能顺序读 raw 的方式。

### 最终方案：单布局三轴共享 + X/Y sidecar

用 Z 布局存储唯一一份 block 数据（写入完全顺序），X/Y 切片用预计算的 sidecar 加速。

## 详细设计

### 文件布局

```
[TriHeader 256B]
[Block data: bz外→by→bx, ZFP压缩] — 三轴共享
[Exception index + data]
[X sidecar: 每个bx对应一个YZ平面, 按bz分段LZ4压缩] — 类似现有 sidecar
[Y sidecar: 每个by对应一个XZ平面, 按bz分段LZ4压缩]
```

### 为什么可行

- Z 切片：读连续 slab（固定 bz），直接解包 ✅
- X 切片：读 sidecar 中固定 bx 的 YZ 平面 ✅
- Y 切片：读 sidecar 中固定 by 的 XZ 平面 ✅
- 写入：block 数据按 z-slab 顺序写（0 寻道），sidecar 也按 z-slab 顺序生成 ✅
- 存储：block 数据 1 份（非 3 份）+ 2 个 sidecar，预计 ~1.5x 以内

### tri_writer.cpp 改动

1. **移除三轴循环**（L245），只处理一次 z-slab
2. **Block 按 Z 布局写**：`blockIdx = bz * (byCount*bxCount) + by * bxCount + bx`
   - z-slab 内 block offset 连续递增，一次 pwrite 写整个 slab
3. **生成 X sidecar**：每个 z-slab 处理时，提取所有 bx 的 YZ 平面数据，按 z-chunk LZ4 压缩追加写
4. **生成 Y sidecar**：同理提取所有 by 的 XZ 平面
5. **异常检测**：只做一次（原 axis==0 逻辑）
6. **Header 更新**：axis_offsets[3] 全指向 block data 区域；新增 sidecar offset 字段

### tri_reader.cpp 改动

1. **Z 切片**（基本不变）：读连续 slab，解包
2. **X 切片**（新）：读 X sidecar 中固定 bx 的压缩 chunk，LZ4 解压，输出 YZ 平面
3. **Y 切片**（新）：读 Y sidecar 中固定 by 的压缩 chunk，LZ4 解压，输出 XZ 平面
4. **axisBlockOffset / axisBlockCount**：Z 轴用 block data，X/Y 轴用 sidecar offset

### tri_format.hpp 改动

Header 增加字段（用 reserved 空间）：
- `x_sidecar_offset`, `x_sidecar_bytes`
- `y_sidecar_offset`, `y_sidecar_bytes`

### sidecar 格式（复用现有 X-plane sidecar 设计）

每个 axis 的 sidecar：
- 索引区：每个 slice index 对应一个 (offset, compressed_size) 条目
- 数据区：每个 slice 的 YZ/XZ 平面按 z-chunk 分段 LZ4 压缩

## 实施步骤

1. 修改 `tri_format.hpp`：增加 sidecar 字段
2. 修改 `tri_writer.cpp`：单布局写入 + sidecar 生成
3. 修改 `tri_reader.cpp`：X/Y 读 sidecar，Z 读 block data
4. 小数据验证（128³）：convert → verify → bench
5. 20GB HDD 测试
6. 50GB HDD 测试

## 关键文件

- `include/erwt3d/tri_format.hpp` — Header 结构
- `src/tri_writer.cpp` — 写入器（主要改动）
- `src/tri_reader.cpp` — 读取器（主要改动）
- `include/erwt3d/tri_reader.hpp` — 读取器接口
- `tools/erwt3d_convert_tri.cpp` — 转换工具（参数可能需调整）
- `tools/erwt3d_bench_tri.cpp` — 基准测试

## 验证

```bash
# 小数据
./build/erwt3d_convert_tri --raw test.raw --output test.erwt3d --nx 128 --ny 128 --nz 128 --rate 16
./build/erwt3d_verify_tri --raw test.raw --erwt3d test.erwt3d --nx 128 --ny 128 --nz 128
./build/erwt3d_bench_tri --input test.erwt3d --output-dir out

# 20GB HDD
./build/erwt3d_convert_tri --raw /d/data/20gb.raw --output /d/data/20gb.erwt3d --nx 801 --ny 2405 --nz 2501 --rate 16 --threads 8 --memory-limit-mb 4096
./build/erwt3d_bench_tri --input /d/data/20gb.erwt3d --output-dir /d/out --hdd
```

## 风险

- sidecar 压缩率：20GB YZ 平面压缩率 0.49x（已知可行），50GB 可能 >1x（需测试）
- 若 50GB sidecar 过大，可只对 X 生成 sidecar，Y 用 block data stride 读 + HDD window
- sidecar 生成增加转换时间，但写入是顺序的，总时间仍远小于当前方案
